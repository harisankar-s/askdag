## Summary

The nightly Airtable sync for the services table failed on 2 February with an expired API token, and the load step wrote an empty extract instead of stopping. By the 3rd, airtable.california_transit__services had no rows for the latest date, so bridge_organizations_x_services_managed rebuilt with no current pairs. Every "services managed by this organization" lookup came back empty.

## Impact

- bridge_organizations_x_services_managed had zero rows valid for 3 February; joins through it returned nothing for current dates.
- The weekly service inventory report went out with "0 services" for every agency before anyone noticed.

## Root cause

A source outage. The sync job treats "no records" as a valid result, so an auth failure upstream looked like an empty base. The staging and dimension models faithfully passed the empty day through.

## Fix

Rotated the token, re-ran the sync for 2 and 3 February, and rebuilt from the services staging model down. The bridge table had 1,184 current pairs again by early afternoon. A correction note went out with the inventory report.

## Follow-ups

- Make the sync fail when the extract has fewer than half the previous day's rows.
- The recovery steps are now in rb-04, so the next person doesn't have to work out the rebuild order.
