## Summary

On 7 January a large share of stops disappeared from the stops dimension for newly processed feeds, the second stops drop in a year. This one had nothing to do with deduplication. Several agencies had moved to a newer GTFS export tool that writes the agency file with an extra column (`cemv_support`) in the middle rather than at the end. Our parse maps columns by position for that file, so the timezone value landed in the wrong field. With no valid timezone, the feeds dimension marked those feeds as incomplete, and the stops for incomplete feeds were not loaded.

## Impact

- About 11% of stops were missing for feeds processed on 6–7 January.
- The stop map and stop-level marts showed gaps for 19 agencies.

## Root cause

A schema change in the source files: a new column in the agency file, and a parser that relied on column order instead of the header.

## Fix

Changed the agency file parse to map by header name, re-parsed the affected feeds, and ran a full refresh of the stops dimension, because it is incremental and would not otherwise restore rows it had skipped.

## Follow-ups

- Map every GTFS file by header, not position; the agency file was the last one that didn't.
- When stops go missing, check whether the feeds themselves are complete before looking at the stops logic.
