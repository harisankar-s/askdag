## Summary

On 11 April about 200 feeds dropped out of the feeds dimension. The parse outcomes for shapes files, the only outcome table produced by a separate parser because shapes files are large, started recording the file name with its folder path (`gtfs/shapes.txt`) after that parser was upgraded. The models that group parse outcomes by feed match on the plain file name, so shapes looked missing for every feed that has one, and feeds with a missing required file are left out.

## Impact

- About 200 feeds were missing from the feeds dimension for 10–11 April.
- Route shapes and every schedule mart for those feeds were missing for the two days.

## Root cause

A schema change in the shapes parse outcomes: the meaning of the file name field changed.

## Fix

Stripped the folder from the file name in the staging step, rebuilt the grouped outcome models and the feeds dimension for the two days, and confirmed feed counts against the previous week.

## Follow-ups

- Add a test that every feed has an outcome for each required file type.
- Ask the parser maintainers to treat the outcome record format as a contract.
