## Summary

A change to stg_gtfs_schedule__agency on 20 March started lowercasing the agency_timezone value along with the other text fields it cleans. Timezone names are case-sensitive in the timezone database, so "america/los_angeles" did not match and dim_schedule_feeds set feed_timezone to null for every feed built after the change. Downstream models that convert local times to UTC fell back to UTC itself.

## Impact

- Arrival times in the daily marts were off by seven hours for feeds built on 20 and 21 March.
- A transit analyst noticed buses "arriving" at 3 a.m. in the trip explorer.

## Root cause

A logic bug in the staging model: a reasonable clean-up rule (lowercase free-text fields) was applied to a field whose case carries meaning. No test checks that feed_timezone is a valid timezone.

## Fix

Reverted the lowercasing for agency_timezone only, rebuilt stg_gtfs_schedule__agency and dim_schedule_feeds, and re-ran the daily marts for the two affected dates.

## Follow-ups

- Add an accepted-values style check that feed_timezone is a known timezone name.
- List the fields that must not be normalised in the staging model's description.
