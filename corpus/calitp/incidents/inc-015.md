## Summary

On 29 September dim_gtfs_datasets showed a null type for 340 datasets. A change to int_gtfs_datasets, which reads the datasets table from Airtable, renamed the type column while tidying names, and the intermediate dimension model downstream still selected the old name through a `select *` and a later rename. The renamed column dropped out and type came through empty.

## Impact

- Filters on dataset type (schedule, trip updates, vehicle positions, alerts) in the quality dashboards returned nothing for those datasets for a day.
- Validation coverage reports skipped the affected datasets.

## Root cause

A logic bug from a column rename in int_gtfs_datasets that wasn't carried through to the models reading it.

## Fix

Reverted the rename in int_gtfs_datasets, rebuilt down to dim_gtfs_datasets, and replaced the `select *` in the intermediate model with an explicit column list.

## Follow-ups

- Add a not-null test on type in dim_gtfs_datasets.
- Prefer explicit column lists in models that sit between Airtable extracts and dimensions.
