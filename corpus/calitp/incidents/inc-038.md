## Summary

On 14 October analysts saw two versions of the same feed starting on the same day for about 400 datasets. A backfill of schedule downloads for 6–12 October, run to recover from a short pipeline pause, downloaded the same zip files again under new download timestamps. The feeds table treats a new download with the same file hash as the same feed only if the timestamps overlap, and the backfill's timestamps didn't, so each feed got a second version.

## Impact

- About 400 datasets had two feed versions for the same day in the feeds table.
- Daily schedule counts doubled for 6–12 October until the rebuild.

## Root cause

Duplicate rows in the feeds table itself: its versioning keys on download time, so a backfill looks like new data.

## Fix

Changed the versioning to merge consecutive downloads with the same file hash, whatever the timestamp, and rebuilt the feeds table and the daily marts for the week.

## Follow-ups

- Add a test that no two consecutive versions of a dataset's feed have the same file hash.
- rb-08 now covers backfills that re-download files.
