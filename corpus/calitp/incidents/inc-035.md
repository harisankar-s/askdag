## Summary

On 26 August dim_gtfs_datasets had two current rows for 18 datasets. int_transit_database__gtfs_datasets_dim builds validity windows for each version of a dataset record, and two Airtable extracts on the same day (a manual re-run on top of the scheduled one) produced versions with the same start time. The window logic ordered by start time only, so the two versions both ended up open.

## Impact

- 18 datasets had two current rows in dim_gtfs_datasets for one day.
- Joins from the RT and schedule marts to datasets doubled for those datasets.

## Root cause

Duplicate rows in int_transit_database__gtfs_datasets_dim from a tie on version start time.

## Fix

Added the extract timestamp as a tie-breaker, rebuilt int_transit_database__gtfs_datasets_dim and dim_gtfs_datasets, and re-ran the affected marts.

## Follow-ups

- Add a test that each dataset has at most one current version.
- How to find and fix overlapping versions in these slowly changing dimensions is in rb-12.
