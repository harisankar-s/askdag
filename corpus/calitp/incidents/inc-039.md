## Summary

On 15 October the stops dimension lost about 8% of stops, the third stops incident on record. This time the cause was in stg_gtfs_schedule__stops: a change to trim and uppercase stop codes also filtered out rows where the stop code was empty after trimming, which was meant to catch bad rows but removed every stop that has no stop code at all, which is allowed by GTFS. dim_stops is incremental, so only feeds processed after the change lost stops.

## Impact

- Rated sev1: the public stop map showed gaps for 26 agencies for a day.
- About 8% of stops were missing from dim_stops for feeds processed on 14–15 October.

## Root cause

A logic bug in stg_gtfs_schedule__stops: stop_code is optional, and the filter treated it as required.

## Fix

Removed the filter, rebuilt stg_gtfs_schedule__stops and ran a full refresh of dim_stops (an incremental run would not bring back the dropped rows), then rebuilt the stop-level marts.

## Follow-ups

- The stop count check per feed suggested after inc-008 had never been added; it has now been added.
- Note in stg_gtfs_schedule__stops which fields are optional in GTFS.
