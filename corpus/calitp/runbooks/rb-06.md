## When to use

Use this when external_gtfs_schedule.download_outcomes stops getting new records although downloads are happening (check the job logs). With no download records, stg_gtfs_schedule__download_outcomes has nothing new, dim_schedule_feeds stops adding feed versions, and when an old feed expires, fct_vehicle_positions_messages can't link messages to a current schedule.

## Steps

1. Confirm the downloads themselves ran: the zip files should be in the bucket for the missing dates.
2. Fix whatever stopped the result records (permissions, worker pool, bucket path).
3. Backfill the result records for the missing dates from the job logs using the backfill script in the pipeline repo.
4. Refresh external_gtfs_schedule.download_outcomes and rebuild: `dbt build --select stg_gtfs_schedule__download_outcomes+`. This rebuilds the feed outcome models and dim_schedule_feeds.
5. Rebuild fct_vehicle_positions_messages for the affected dates.

## Check

- dim_schedule_feeds has new feed versions for the dates in the gap.
- Every vehicle positions message in the gap has a schedule feed, apart from agencies that genuinely have none.
- The freshness check on download results is green.
