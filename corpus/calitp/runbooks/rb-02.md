## When to use

Use this when airtable.california_transit__gtfs_datasets has no rows, or fewer than expected, for the latest extract date. You'll usually notice it downstream: bridge_schedule_dataset_for_validation is empty, RT validation produced no notices, or base_tdqi_gtfs_datasets_ct_gtfs_datasets_map can't link data quality issues to datasets.

## Steps

1. Check the sync job's result first. If it failed, find out why (Airtable status page, token expiry, base ID).
2. Don't rebuild until a sync has succeeded; rebuilding against an empty extract makes it worse.
3. Re-run the sync for the missing date.
4. Rebuild from the datasets staging model: `dbt build --select stg_transit_database__gtfs_datasets+`. This covers bridge_schedule_dataset_for_validation and base_tdqi_gtfs_datasets_ct_gtfs_datasets_map.
5. Re-run RT validation for any day that was validated against an empty mapping.

## Check

- The row count of the latest extract is within 5% of the previous day's.
- bridge_schedule_dataset_for_validation has one schedule dataset for every active RT dataset.
- RT validation notice counts are back to their usual range.
