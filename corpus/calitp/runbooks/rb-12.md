## When to use

Use this when a versioned dimension has more than one current row for an entity, for example dim_gtfs_datasets. The versions are built in int_transit_database__gtfs_datasets_dim from Airtable extracts; two extracts with the same timestamp, or a re-run on the same day, can produce versions that overlap.

## Steps

1. Find entities with more than one current row, or with versions whose validity windows overlap.
2. Look at the extract timestamps for those versions. Ties are the usual cause.
3. Make sure the version ordering has a tie-breaker (the extract timestamp, then the record's modified time).
4. Rebuild int_transit_database__gtfs_datasets_dim and dim_gtfs_datasets, then the marts that join to datasets.

## Check

- Each dataset has exactly one current row in dim_gtfs_datasets.
- No two versions of the same dataset overlap in int_transit_database__gtfs_datasets_dim.
