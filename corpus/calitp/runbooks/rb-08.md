## When to use

Use this when dim_schedule_feeds shows two versions of the same feed starting on the same day, or consecutive versions with the same file hash, usually after a backfill re-downloaded files.

## Steps

1. Find datasets with consecutive feed versions that have the same zipfile hash in dim_schedule_feeds.
2. Check whether a backfill ran for those dates. If it did, the re-downloads are the cause.
3. Make sure the versioning merges consecutive downloads with the same hash, regardless of the download timestamp.
4. Rebuild dim_schedule_feeds in full and the daily schedule marts for the affected dates.
5. Before the next backfill, run it in dry-run mode and compare hashes first.

## Check

- No dataset has two consecutive versions with the same hash in dim_schedule_feeds.
- Daily scheduled trip counts for the backfill window are back to normal.
