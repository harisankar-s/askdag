## When to use

Use this when a dimension that should have one current row per entity has more, for example dim_county_geography with two rows for the same county. The usual causes are a join added to the dimension that belongs in a bridge table, or a change in grain that kept the old name.

## Steps

1. Find the duplicated keys: group the current rows of dim_county_geography (or the affected dimension) by its key and keep groups with more than one row.
2. Compare two duplicate rows column by column. The column that differs tells you which join fanned out.
3. Move that relationship into a bridge model (one row per pair), and remove the column from the dimension.
4. Point any report that needs the new relationship at the bridge.
5. Rebuild the dimension and everything downstream.

## Check

- The uniqueness test on the dimension's key for current rows passes (add it if it isn't there).
- Counts by county in downstream reports match the previous week.
